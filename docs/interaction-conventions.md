# WebPOS 操作一致性規範

## 設計依據與選擇

本系統固定採用「取消／返回在左，確認／儲存在右」。桌面、平板、手機直向及橫向都維持同一順序。

左右順序並沒有跨平台唯一答案。[Nielsen Norman Group](https://www.nngroup.com/articles/ok-cancel-or-cancel-ok/) 說明 Windows 與 Apple 的慣例不同，並強調一致性與使用者預期。本系統既有 M3 元件，採用 [Material Design 的 dismiss-left / affirmative-right 規則](https://m1.material.io/components/dialogs.html)，與 [Material Web 的 Cancel → OK 範例](https://material-web.dev/components/dialog/) 一致。這是 WebPOS 的產品決策，並非宣稱所有網站都應採用同一排列。

本地 ui-ux-pro-max 資料集沒有找到可驗證的按鈕左右順序規則，因此以上述公開指引作為順序依據。鍵盤及焦點行為依 [W3C APG Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)；主要操作的層級與文案亦參考 [Carbon 按鈕指引](https://carbondesignsystem.com/components/button/usage/)。

## 必須遵守的規則

1. **位置**：同組操作先放取消／返回／清空等次要操作，再放確認／儲存／送出等主要操作；操作區靠右。每組只有一個主要操作。
2. **手機**：確認與取消維持並排，文字可在自己的按鈕內換行。輔助操作與金額摘要可另成一列，不把取消移到主要操作下方。
3. **DOM 與鍵盤**：HTML 順序就是視覺順序，不使用 `order`、`row-reverse`、`column-reverse` 或正數 `tabindex` 翻轉操作。Tab／Shift+Tab 保持在最上層視窗，Esc 只取消最上層操作，關閉後返回原操作位置。
4. **層級**：確認／儲存使用 Filled primary；取消／返回／清空使用 Quiet；刪除／移除確認使用 danger。同組操作區按鈕觸控高度至少 48px，間距至少 8px。
5. **文案**：說明實際結果，例如「刪除商品」「移除成員」「列印一份」「確認送出訂單」。一般取消用「取消」，流程返回可用「上一步」「返回修改日期」。草稿恢復使用「暫不恢復／繼續編輯」。
6. **退出**：取消、Esc 與可關閉的背景點擊不執行確認操作。草稿暫不恢復時保留原草稿；初始權限與購物車渲染不得覆寫它。使用者開始新的訂單操作後，沿用原草稿保存流程。
7. **焦點與危險操作**：刪除、移除、完成訂單與超量送單的初始焦點放在取消，避免連按 Enter 誤確認。表單開啟不自動聚焦輸入框；確認操作只由明確啟動主要按鈕或提交表單觸發。
8. **載入**：沿用現有表單送出鎖定、進度與失敗後保留輸入。確認回呼在執行前消耗並關閉，避免同一次確認重複執行；較晚回覆不得關閉另一個新確認視窗。非同步確認後重新確認店鋪／成員仍是原操作對象。
9. **頁首**：返回箭頭在左，關閉 X 在右。提交類表單在底部仍提供取消，不讓使用者只能找 X 離開。

## 全專案操作盤點

| 操作區 | 左側操作 | 右側操作 | 處理方式 |
| --- | --- | --- | --- |
| 客戶資料 | 清空資料 | 儲存並下一步 | 共用操作區與主次樣式 |
| 訂單查詢 | 清空條件 | 搜尋訂單 | 修正原本主要操作在左的順序 |
| 禮盒選品／確認 | 重選規格／上一步 | 下一步／加入購物車 | 金額摘要另列，按鈕共用排列 |
| 購物車商品刪除 | 滑回／Escape 收起 | 右側刪除／持續長滑後放開刪除 | [兩段式刪除與過渡規範](cart-swipe.md) |
| 商品詳情 | 取消 | 加入購物車 | 補上底部取消入口 |
| 商品新增／編輯、訂金 | 取消 | 儲存／確認設定 | 使用同一元件與樣式 |
| 通用確認、商品刪除 | 取消 | 具體確認動作 | 共用視窗，危險操作使用紅色 |
| 日期覆寫刪除 | 取消 | 刪除設定 | 取代瀏覽器原生確認框 |
| 草稿恢復 | 暫不恢復 | 繼續編輯 | 取代原生確認框，取消保留草稿 |
| 超量送單 | 返回修改日期 | 確認送出訂單 | 共用操作區，取消釋放送單鎖 |
| 訂單詳情 | 關閉 | 標記完成 | 編輯／列印維持輔助操作區 |
| 訂單完成／刪除 | 取消 | 滑動完成／滑動刪除 | 保留滑動保護，移到取消右側；鍵盤替代操作保留 |
| 商品排序 | 取消 | 儲存順序 | 捨棄調整的重新載入另列 |
| 列印設定／預覽 | 測試列印／關閉 | 儲存列印設定／列印一份 | 修正主要操作原本在左的順序 |
| 下單成功提示 | 關閉 | 列印訂單 | 動態按鈕亦共用操作區，狀態文字另列 |
| 登入／設定密碼 | 建立帳號／取消 | Email 登入／設定登入密碼 | 登入選項為次要操作，所有憑證操作共用載入鎖 |
| Email 驗證 | 改用其他帳號 | 我已驗證，重新檢查 | 重寄信獨立放在上方 |
| 店鋪建立、設定、成員表單 | 取消／返回店鋪列表 | 建立／儲存／新增 | 固定底部補上取消入口 |
| 成員移除 | 取消 | 移除成員 | 共用確認、保留 owner 保護 |
| PWA 安裝／更新提醒 | 稍後／稍後再說 | 安裝／查看更新 | 修正安裝順序，沿用更新延後流程 |

日期選擇器的今天／清除／關閉、數量的減／加、查詢捷徑、導覽、分頁、店鋪清單入口及單一報表產生按鈕依各自功能排列；它們不是提交與取消的成對決策。日期選擇及自動儲存設定維持原本即時生效方式。

## 共用實作與維護

```html
<div class="gj-actions">
  <button type="button" data-action="dismiss" class="gj-btn gj-btn--quiet">取消</button>
  <button type="button" data-action="primary" class="gj-btn gj-btn--primary">儲存</button>
</div>
```

清空／測試／建立帳號等非退出的次要動作使用 `data-action="secondary"`。安全初始焦點加上 `data-dialog-initial-focus`。共用視窗呼叫 `requestConfirmation(message, { title, confirmLabel, cancelLabel, danger, opener })`，按確認回傳 `true`，取消／Esc／關閉回傳 `false`。由按鈕開啟時傳入 `opener`，讓 Safari 沒有自動聚焦按鈕時，仍能在取消後返回正確入口。

樣式來源為 `../web-ui-kit/styles/components.css` 的 `gj-actions` 與 `styles/pos.css` 的畫面適配，並同步同一區塊至本專案快照。保留兩份 `pos.css` 的其他既有差異，不整檔覆寫。一般建置仍使用專案內快照。

驗收檢查實際按鈕座標、DOM 順序、觸控尺寸、視窗內可見性、深淺色、320px 手機與橫向；另驗證取消沒有寫入、Esc 只關閉最上層、焦點返回、草稿延後恢復、重複確認及原訂單／付款／列印／成員權限流程。
