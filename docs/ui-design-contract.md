# WebPOS 介面設計契約

WebPOS 是營運工具。畫面優先呈現姓名、日期、品項、數量、金額與操作狀態，避免以裝飾填滿頁面。

## 品質提升順序

以 Awwwards、Webby Awards、FWA 得獎作品的完成度為品質標竿；獎項屬於外部評審結果，不能由自動測試或自行評分宣稱達成。

依使用者指定，從通用功能到特定功能逐層檢查：

1. 共用基礎：資訊層級、字體、主題、響應式、焦點、鍵盤操作、通知與錯誤回饋。
2. 可重用互動：表單、建議清單、日期選擇、查詢、對話框、載入／空白／失敗狀態。
3. 訂單流程：客戶、交貨日期、商品、禮盒、購物車、付款與訂單編輯。
4. 管理工具：商品、供應量、需求統計、營業報表、帳號／店鋪與出單機。

每輪先確認可重現問題，再修改、執行相關回歸並檢視實際畫面。沿用既有品牌與共用樣式來源，避免為增加裝飾而降低營運效率。保留未解決限制與實際驗證範圍，不將「測試通過」等同「已達得獎標準」。

### 2026-10-01：導覽、通知與客戶輸入

- 瀏覽器上一頁／下一頁回到頁面標題焦點，與直接導覽一致。
- 通知在滑鼠停留或鍵盤聚焦時暫停倒數；使用關閉按鈕明確關閉，減少動態偏好下立即移除。
- 客戶姓名與聯絡方式皆空白時，在欄位旁保留錯誤說明、標記無效狀態並聚焦姓名；有效輸入後清除錯誤。
- 降低共用表單底色／邊框預設樣式的選擇器權重，避免覆蓋焦點與錯誤狀態。來源元件庫與本專案快照套用同一修正；兩份 `pos.css` 原有其他差異保留，未整檔同步覆寫。
- 客戶建議清單支援方向鍵、Enter 選取、Escape 關閉與讀屏狀態；舊查詢回覆、離開欄位或切換頁面後的回覆不再重開清單。
- LINE 模式使用「聯絡方式」標籤；取消稱謂與選取建議客戶後排程保存草稿。

既有 iOS 縮放限制及其 `meta-viewport` 測試例外仍保留。本輪不宣稱完整 WCAG 符合性或獎項等級已達成。

### 2026-10-01：查詢狀態與訂單結果

- 查詢區提供初始指引、載入提示、可採取下一步的空結果文字，以及可重試的錯誤狀態。
- 一般查詢、逾期查詢與分頁共用請求版本控制；新查詢或清空條件後，舊成功／失敗回覆不再改動畫面。清空同時取消舊明細展開動畫的後續更新。
- 逾期查詢失敗的重試仍查詢逾期訂單；結果區使用穩定焦點，分頁結束後保留鍵盤操作位置。

- 已付清訂單的剩餘金額保留 0；總額、訂金、剩餘金額與運費使用千位分隔。僅修正顯示，付款計算與寫入流程未變更。

### 2026-10-01：訂單明細展開控制

- 在客戶姓名旁提供原生展開按鈕與方向箭頭，支援 Enter／Space；保留整列點擊展開。44px 最小觸控高度，長姓名完整換行。
- `aria-expanded` 回報狀態，展開時 `aria-controls` 指向商品明細；可存取名稱包含客戶與訂單編號，區分同名客戶。
- 表格重繪後恢復原展開按鈕焦點，切換另一筆訂單與收合動畫均不把焦點丟回頁面；使用者移到其他欄位後不搶回焦點。
- 搜尋結果標題改為 h2，接續頁面 h1；調整平板列內留白，保留既有緊湊高度驗收。
- 修正減少動態模式停在透明／零高度的問題，展開明細與空明細提示直接顯示。
- 共用樣式在 `../web-ui-kit/styles/pos.css` 與本專案快照套用相同新增區塊，保留兩份檔案原有其他差異。

驗證：初次巡檢發現平板列高超出既有標準、結果標題層級跳級，修正後 36 項跨平台表格／焦點／分頁／動畫檢查通過，12 項平台限定略過。截圖複查再發現減少動態模式明細不可見，修正後新增透明度與實際可見性斷言；最後 16 項鍵盤、一般／減少動態與全站深淺色檢查全部通過。`npm run check` 通過，已查看桌面及手機截圖，產物已重新建置，未部署。

### 2026-10-02：POS、訂單、商品與登入的核心品質檢查

- 登入：保留可見 Email／密碼標籤、密碼管理工具與貼上支援；加入密碼顯示控制、欄位錯誤與可連到欄位的摘要。Enter 提交登入；重設密碼只檢查 Email。非同步操作提供文字進度並避免重複登入或同時建立帳號，失敗保留輸入，成功離開登入畫面後清除密碼。常見密碼錯誤、網路中斷、次數限制與登入視窗問題依 [Firebase Auth 官方錯誤代碼](https://firebase.google.com/docs/reference/js/auth) 提供中文恢復指引。
- 商品：必填錯誤持續留在欄位旁，錯誤摘要可直接聚焦欄位；選擇既有類別同樣清除正確的錯誤。儲存失敗保留草稿與重試說明，儲存中避免修改正在送出的欄位；較晚回覆不關閉新開啟的編輯視窗。商品管理篩選提供選取狀態並保留鍵盤焦點，空白清單依成員權限提供下一步。
- POS：結帳區直接列出尚缺的客戶、日期與商品，提供前往下一步的操作。顯示離線／僅檢視原因；有運費時分列商品小計與運費，再呈現總額。沿用原計價與送單規則。
- 訂單：訂金超額與負值提供文字原因、無效狀態與欄位關聯；失敗保留金額與備註，允許重試。較晚完成的付款回覆不關閉另一筆訂單的設定視窗。訂單查詢、明細、狀態確認與原有付款計算列入回歸。
- 共用樣式：欄位回饋使用既有語意色彩、系統字體與留白。登入在窄螢幕／短視窗可捲動；保留 16px 輸入字級、觸控大小與焦點。先更新 `../web-ui-kit`，再套用同一新增區塊至快照；未整檔覆寫兩份 `pos.css` 的既有差異。

自我檢查採用「確認缺陷 → 實作 → 行為回歸 → 實際截圖複查」循環：第一輪檢查登入、商品編輯與 POS；第二輪檢查非同步回覆、重試與結帳；第三輪延伸到訂金、375px 手機、橫向與深淺色。第四輪在完整回歸通過後的截圖中發現橫向購物車商品區過窄，改為緊湊摘要、總額與結帳並列，並清除抽屜標題的瀏覽器預設 margin。新增驗收要求商品區至少 160px、數量控制完整可見，沒有降低原驗收門檻。另以完整本機應用程式搭配模擬登入檢查失敗後的焦點與背景鎖定；未連接正式帳號或訂單。

## 實作規則

| 項目     | WebPOS 規則                                                                |
| -------- | -------------------------------------------------------------------------- |
| 字體     | 標題、內文與按鈕使用同一套繁體中文系統字體，不使用手寫展示字體             |
| 字級     | 桌面頁標題 28px、手機 24px、品項 16px、內文 16px、說明 14px、輔助標籤 12px |
| 間距     | 以 8、16、24px 為主要級距；同組欄位間距一致                                |
| 頁首     | 一個標題加一句必要說明，不重複顯示品牌口號                                 |
| 訂單摘要 | 一條可操作的摘要列；手機客戶、日期、購物車並列，不占兩排卡片               |
| 表單     | 欄位透過標籤與留白分組，不加無用途的外層灰色卡片                           |
| 按鈕     | 主要動作 Filled；清空／返回使用 Text；桌面按內容寬度排列，手機保持觸控大小 |
| 商品清單 | 直接顯示品名、價格與操作；沒有實際商品圖片時，不以重複的泛用圖示代替       |
| 數據     | 金額與數量以等寬數字對齊；一般價格使用文字色，狀態與欠款才使用語意色       |
| 裝置資訊 | 唯讀資料以標籤／值的資料列呈現，避免看起來像可編輯表單                     |
| 動態     | 只為操作回饋服務；商品卡不浮起，保留已修復的購物車 220／160ms 過場         |
| 維護     | 先修改 `web-ui-kit` 的共用樣式，再同步與建置；保留既有 ID、權限與業務事件  |

## 驗收

以 375／390px 手機、平板、桌面與 WebKit 檢查 Light／Dark、鍵盤操作、焦點、橫向溢出及原有訂單流程。自動掃描通過不能取代完整人工無障礙認證；既有縮放限制另外記錄。

### 0.15.4 發布驗證（2026-10-02）

介面、登入回饋、結帳與紙本單據更新一併發布。版本建置與頁尾同步為 0.15.4，重新產生 CSS／JavaScript／Wasm 與 PWA 快取。`npm run build` 完整通過：Rust 6 項、Node 35 項、瀏覽器 546 passed／18 skipped（平台限定）。已核對版本指紋與完整 app shell 的快取指紋一致。紙本仍以點陣與模擬傳送驗證，未操作實機出紙。

### 0.15.6：訂單商品明細過渡（2026-10-02）

展開／收合維持 280ms／220ms。明細與後續訂單列先計算目標版面，再以位移及透明度呈現過渡；快速反向操作沿用相同明細節點，從目前位置與透明度接續。外框邊緣可見或捲動位置可能被截短時，僅調整獨立外框的高度，保留最後一筆的退出與頁尾移動；長清單的螢幕外邊緣直接採用目標高度。動畫結束後移除臨時樣式，清空或重新搜尋會取消舊動畫。

浮動捲動條改為先讀取所有區域的位置，再批次寫入代理控制項樣式，減少交錯讀寫造成的重排。此做法參考 [web.dev 的版面計算與讀寫批次原則](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing)。共用樣式來源與本專案快照同步新增動態 tokens，保留其他既有差異。

本機 Chromium、CPU 4 倍降速，以 30 筆訂單、每筆 20 個品項，各展開／收合五輪：1440px 與 390px 的 LayoutCount 由 331／341 降為 55／55，LayoutDuration 由 141／87ms 降為 35／25ms；RecalcStyleCount 由 4025／3858 降為 368／368。這是相同測試情境的瀏覽器計數，沒有宣稱真機 FPS 或所有訂單資料的固定改善比例。

已驗證動畫中途反向時的節點、位置與透明度連續性，最後一筆在退出中仍可見，並檢查手機深淺色與 WebKit 實際截圖。針對性回歸 65 passed／15 skipped（平台限定），另有 8 項連續性與 4 項可見退出畫面檢查通過。`npm run build` 完整通過：Rust 6 項、Node 40 項、瀏覽器 554 passed／18 skipped（平台限定）；Firebase 模擬器整合通過。0.15.6 的頁尾、版本及完整 app shell 快取指紋已核對一致。

### 0.15.7：更新提醒與店鋪切換（2026-10-02）

手機更新提醒改為從「管理」入口出現的訊息泡泡，箭頭對準入口。「稍後再說」會記住此頁籤在目前版本的選擇，重新載入也不重複提醒；管理入口與裝置資訊保留更新標示。「查看更新」先開啟裝置資訊，由使用者決定更新時間，並保留未完成訂單的保護與更新進度回饋。

店鋪切換在手機使用底部面板，平板與桌面使用置中視窗。預設僅呈現店鋪清單、目前使用狀態及建立／設定入口；建立店鋪、店鋪資料、成員清單、新增成員與成員權限編輯分開呈現。返回、關閉與主要動作位於固定區域，長清單在內容區捲動。新增成員欄位採單欄配置、可見標籤與 Email 鍵盤；擁有者維持不可移除及不可變更權限。

成員資料僅在進入成員頁時載入，切換店鋪不再等待成員查詢。表單錯誤保留輸入並可重試；離開建立畫面後，稍晚完成的建立請求不會自動切換店鋪。關閉視窗後，待帳號入口顯示過渡完成再恢復焦點；首次必要的店鋪選擇仍不可略過。

已檢查 320／375px 手機、橫向、平板、桌面、深淺色與 WebKit 截圖；店鋪及啟動流程的 76 項針對性回歸、登入與按鈕狀態回歸通過。版本建置與頁尾同步為 0.15.7，CSS／JavaScript 與 app shell 快取重新建置。

發布前 `npm run build` 完整通過：Rust 6 項、Node 40 項、瀏覽器 602 passed／18 skipped（平台限定）。頁尾、系統版本與完整 app shell 快取指紋已核對一致；推送後由 GitHub Actions 執行模擬器整合及部署驗證。
